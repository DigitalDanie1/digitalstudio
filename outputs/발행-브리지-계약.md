# FIELDNOTE 발행 브리지 계약

이 HTML은 승인된 원고를 `POST`로 보냅니다. 실제 플랫폼 로그인, OAuth 토큰, 영상 파일과 미디어 업로드는 이 브리지에서만 처리합니다. 브리지는 개인 서버 또는 신뢰할 수 있는 자동화 워커로 운영하세요.

## 요청

연결 설정에 채널별 URL을 넣습니다. 예: `https://publisher.example.com/publish/youtube`

```json
{
  "version": 1,
  "action": "publish",
  "channel": "youtube",
  "post": {
    "id": "원고-id",
    "title": "제목",
    "body": "원고 본문",
    "sources": "출처",
    "approvedAt": 0
  },
  "profile": { "name": "워크스페이스", "tone": "편집 원칙" }
}
```

토큰을 입력한 경우 `X-Fieldnote-Token` 헤더가 함께 전송됩니다. 브리지는 CORS에서 `Content-Type`, `X-Fieldnote-Token`, `POST`, `OPTIONS`를 허용해야 합니다.

## 응답

즉시 게시가 끝난 경우:

```json
{ "ok": true, "state": "published", "url": "https://...", "message": "게시 완료" }
```

예약 또는 영상 처리 대기라면:

```json
{ "ok": true, "state": "queued", "message": "처리 대기" }
```

실패 시 HTTP 오류 또는 `{ "ok": false, "message": "사유" }`를 반환합니다.

## 채널별 구현 기준

- YouTube: Google OAuth의 `youtube.upload` 권한으로 `videos.insert`를 사용합니다. 원고 외에 실제 동영상 파일 또는 브리지가 접근 가능한 파일 URL이 필요합니다. [공식 업로드 문서](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert)
- Instagram: Meta 앱, Business/Creator 계정 권한, 게시 가능한 이미지·릴스의 공개 URL이 필요합니다. 원고만으로는 게시할 수 없습니다. [Instagram 플랫폼 문서](https://developers.facebook.com/docs/instagram-platform/)
- 네이버 블로그: 현재 NAVER Developers의 공개 API 목록에서는 일반 블로그 글쓰기 API를 확인하지 못했습니다. 따라서 브리지는 본인 계정용 수동 세션 기반 자동화 또는 향후 공식 제휴 API로만 구현하세요. 캡차·차단을 우회하거나 타인 계정에 접근하는 방식은 쓰지 마세요. [NAVER 공개 API 목록](https://developers.naver.com/products/intro/plan/plan.md)

## 운영 규칙

브리지는 `approved` 상태 원고만 수신해도 다시 검증하고, 발행 전 제목·출처·미디어 권리·개인정보·예약 시각을 검사해야 합니다. 플랫폼 비밀번호와 OAuth client secret은 HTML, Git 저장소, 브라우저 localStorage에 넣지 않습니다.
